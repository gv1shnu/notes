Pending & limits (from STATUS / guarantees)

  • It's a dev prerelease (0.1.0-dev.2): cloud operation and sustained capacity are not certified.
  • Single broker + non-HA JobManager; source process state isn't durable.
  • Checkpoints don't imply end-to-end exactly-once delivery.
  • Manifest reconciliation can be expensive at larger volumes — filter one run, use indexes.
  • The target 5–15 s backend / 10–30 s dashboard freshness is not yet evidenced.

Rebuild it from scratch

  1. Contracts
    Define events.v1 JSON schema + Pydantic models; four source loops in one process emitting with emitted_at, event_id, run_id.
  2. Kafka
    Single-broker KRaft; a topic per source; a DLQ and a late topic.
  3. Flink job (Java)
    Deserialize + validate contracts → side-output rejects; key by identity, dedupe with 24h TTL; event-time watermarks + idleness; windows for server stats; idempotent JDBC sink + checkpointing.
  4. Warehouse
    Canonical fact tables, manifest table, reconciliation that flips provisional→final, live mart views, least-privilege roles.
  5. dbt
    Staging + marts + a historical player-match model; add tests (unique placements, one winner, reconciled totals, server bounds).
  6. Observability
    An exporter reading real broker offsets, row counts and Flink checkpoint status; Prometheus scrape.
  7. Superset in code
    bootstrap.py creates the DB connection, datasets and all charts/dashboards; export them to YAML.
  8. Orchestration + proof
    Airflow DAG (pin → archive → reconcile → dbt → export → finish); fault-injection and benchmark scripts that write evidence JSON; a Playwright script that proves live refresh.
  9. Package
    Docker Compose + a Makefile (bootstrap/demo/bi-up/status/scenario); loopback-only admin ports; a static Pages showcase.
