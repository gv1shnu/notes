The problem

Drop in a video and get meme reactions added exactly when the funny moments happen — a surprised face, a facepalm, a fall, a snack grab, an awkward silence — stickers that follow the person they're reacting to.

The hard constraint I set: everything runs in the browser. The video is analysed on-device with MediaPipe and never uploaded. The only server code is a tiny proxy that keeps the GIPHY key secret.

The pipeline

What makes it work (and the clever bits)

  • The whole clip is known, so a cue can be confirmed as sustained but stamped at its true onset — accurate timing without false positives.
  • Camera motion fools everything. A cut/pan/tilt reads as people moving unless you estimate global shift first (camera.ts: pixel + colour-histogram change).
  • Timing is comedy. A reaction placed on the exact frame isn't funny; each event type has a timing mode — instant (surprise, jump), beat (facepalm, laugh), or delayed — and the delay is seeded so plans are reproducible.
  • Not every event deserves a meme. The planner scores funniness, enforces spacing + per-type cooldowns + a density budget, so the video never drowns in stickers.
  • Distant faces get an upscaled head-crop pass; crowd pose-model hallucinations are dropped by plausibility gates.

privacy by construction

No uploads, no face recognition, no persistent identity. People get session-local ids (P1, P2…) that reset at every camera cut and never outlive the page.
the proxy only accepts the app's own fixed search terms, so the GIPHY key can't become an open search proxy.
