The problem

Normalisation is taught as seven separate definitions with seven unrelated toy tables. Students memorise "no partial dependency" without ever seeing a table split.

I wanted one student database that travels from a messy spreadsheet (UNF) all the way to 5NF, where every step's output is literally the next step's input, shown before/after, side by side.

The whole journey on one page

What I observed while building

  • My first model was wrong: the toy data didn't actually exhibit the anomaly each step claimed to fix. A 5NF example only works if joining two of the three pair-tables invents a "phantom" row. I fixed the data and wrote selftest.js to prove it.
  • Random data per visit is good for practice, but the schema must never change with the seed, only the values.
  • Showing every table at every step drowns the change. Collapsing carried-forward tables keeps the eye on the split.
  • Students confuse a plain composite-key column (e.g. Hobby) with a foreign key. FK chips only appear when the referenced table is present.

4NF vs 5NF in one sentence

4NF: two independent lists (hobbies, languages) multiplied together. 5NF: three facts that only make sense together, so you need all three pair tables to rebuild it, and any two of them invent rows.
