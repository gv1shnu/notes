The problem

When I open a website, what does it learn about me (trackers, cookies, fingerprinting) and what does it ask from me (forms)? Browser devtools show it, but not in a way a student can read.

Built as a teaching project on data privacy and DBMS: a curated tracker table is "joined" against everything a live page loads and does, then grouped into an organised report with a 0–100 privacy score.

The observation that decided the design

What else I observed

  • It can't be a static site. Same-origin policy blocks reading another site's response from the browser, and a headless browser can't run in a page. So: a backend.
  • Ad-heavy pages never reach network idle; navigation must time out gracefully and keep whatever loaded.
  • Fingerprinting is invisible in the network tab; you only catch it by wrapping the APIs before site code runs.
  • A URL-taking server is an SSRF risk: someone could ask it to scan localhost or the cloud metadata IP.
  • Some sites block bots or hide behind consent walls; results are partial and the UI has to say so.

scope line

Results are best-effort and educational, not a legal privacy audit.
