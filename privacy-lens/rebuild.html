How I judge it

  • Detection gap fast vs deep (cnn.com: ~4 vs 11 trackers, 235 hosts, 53 cookies, 8 probes).
  • Scan time reported as tookMs in every result.
  • Degradation rate: how often the deep scan falls back (shown to the user).
  • Safety: private/internal targets always rejected.

Pending

  • Grow trackers.json (or import an open tracker list) to shrink "other third-party".
  • Reuse one browser with a page pool + a scan queue, so concurrent users don't OOM the free instance.
  • Rate-limit /api/scan.
  • Re-check the resolved IP at connection time (DNS rebinding can bypass a lookup-then-connect check).
  • Cache recent results per domain for a few minutes.

Rebuild it from scratch

  1. Express skeleton
    express.static("public"), /api/health, /api/scan returning {ok, result} or 400.
  2. Guard first
    normalizeUrl (add https://, require http/https) and assertPublicHost with the ranges above.
  3. Fast scan
    fetch HTML, cheerio: collect script/img/iframe/link hosts, parse set-cookie, detect forms.
  4. Tracker table + classify
    for each third-party host, find the first pattern contained in it; group by category.
  5. Deep scan
    Puppeteer with the probe injected on new document; request log; networkidle2 + settle; read storage, cookies, forms.
  6. Score + UI
    scoring weights; a search box, a deep/fast toggle with a "can take 30–40 s" warning, cards per category.
  7. Deploy
    Dockerfile from node:20-slim + Chromium libs + unzip; render.yaml with Docker runtime and health check.
