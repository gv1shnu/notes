The SnapshotBuffer (the heart of the smoothing)

push(state, serverTime, seq, received): drop out-of-order (seq ≤ last) offset = min(offset, received − serverTime) // clock align reset boundary clears the buffer keep at most 20 snapshots sample(now): time = now − offset − delay // delay = 100ms drop snapshots older than `time` (keep ≥ 2) interpolate x/z linearly between the two around `time` angles via normalizeAngle

Each peer is drawn at now − 100 ms, so there are almost always two real snapshots bracketing that moment to interpolate between — the car glides instead of snapping.

the clock offset is tracked as a running minimum, which self-corrects for latency without a handshake.

a change in the reset flag flushes the buffer so a respawn doesn't interpolate across a teleport.

Server & rooms

Lap validity

  • Timing starts only when you cross the start line forward; the circuit must be completed in checkpoint order.
  • Off-track, respawn, reversing through checkpoints, or a paused (backgrounded) tab invalidate the current lap.
  • Cross the start line again to begin a fresh attempt.

Testing a real-time game

  • Unit: physics, input, protocol, server (npm test).
  • e2e: Playwright across Chromium/Firefox/WebKit.
  • Soak (scripts/soak.mjs): 60 local clients for 2 minutes — shakes out room/memory/socket issues.
  • Churn (scripts/churn.mjs): rapid join/leave.
  • Record (scripts/record-race.mjs): 3 scripted WebSocket clients with separate racing lines → a WebM capture + results.
  • /healthz reports room counts, memory, socket queues; /#debug shows frame timing + renderer resource counts.
