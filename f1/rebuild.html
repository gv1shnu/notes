How I judge it

  • Smoothness: do remote cars glide, or teleport, under packet loss?
  • Lap integrity: are off-track / reversed / paused laps correctly invalidated?
  • Soak: 60 clients × 2 min without a memory/socket blowup.
  • Cross-browser: Playwright passes on Chromium, Firefox, WebKit.
  • Frame timing via /#debug; server health via /healthz.

Rebuild it from scratch

  1. Shared track + physics
    A circuit module and a 60 Hz fixed-step car model that both the client renders and the server can validate against.
  2. Local game loop
    Three.js scene, three cameras, input, engine audio; drive single-player first.
  3. Protocol
    Define state/peer message shapes and validators; a sequence number and server time on every snapshot.
  4. Server rooms
    Node WebSocket server: assign drivers to rooms (≤ capacity), validate incoming state + lap progress, broadcast snapshots at 20 Hz; /healthz.
  5. Snapshot buffer
    Client-side: align clocks by a running-min offset, keep ~20 snapshots, sample at now − 100 ms, interpolate position/angle; flush on reset.
  6. Lap rules
    Start-line-forward timing, ordered checkpoints, invalidation on off-track/respawn/reverse/pause; a leaderboard HUD.
  7. Robustness
    Reconnect logic + watchdog; off-track prompt + auto-respawn; bundle pinned deps into hashed assets.
  8. Test + ship
    Unit + Playwright + a soak harness + a scripted-client race recorder; Dockerfile + Render blueprint.
