The problem

I want my personal CS notes online — searchable, linkable, on GitHub Pages — but the repo is public, so everything committed is world-readable forever.

The whole project is a publishing pipeline with one invariant: only ciphertext is ever committed. Plaintext notes live gitignored on my machine; a verification gate refuses to publish if anything would leak.

The one invariant

What the design has to defend against

  • Content: every page's body is AES-256 encrypted; the reader unlocks once per browser tab and the derived key lives only in sessionStorage, discarded when the tab closes.
  • Paths: topic names in URLs would leak the content, so every directory/file is renamed to an opaque token — derived by a memory-hard KDF, so a seen path+token pair can't be brute-forced at raw-hash speed.
  • Metadata: titles are forced to a neutral "Private notes"; descriptions and OpenGraph/Twitter tags are stripped.
  • Assets: CSS/JS/images are inlined into each page before encryption, so nothing ships as a cleartext sidecar; orphans are swept.
  • Search: the full-text index is built then injected into index.html before encryption, so it ships encrypted and only works after unlock.

unlock once, browse all

A fixed shared salt (.staticrypt.json) means a reader unlocks once per tab and can then browse every page in that session.
the commits are literally "commit #1", "commit #2", "commit #3" — sequential, by design.
