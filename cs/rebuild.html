Every commit is ciphertext only, so the git history itself leaks nothing — not even a meaningful message. The interesting evolution is in the toolchain, which lives in the working tree.

How I judge it

  • Zero-leak: verify.sh passes — no plaintext fragment, email, key or credential in docs/.
  • Only ciphertext committed: every file in docs/ is an encrypted HTML page (or .nojekyll).
  • Round-trip: decrypt.sh reconstructs the plaintext from the committed ciphertext.
  • Usability: unlock once per tab, search works, links resolve across obfuscated paths.

Pending

  • Run verify.sh in a pre-push hook / CI so a manual publish can't skip the gate.
  • Rotate the password periodically (it reshuffles every token — plan for the churn).
  • Consider per-section passwords for selectively sharing a subtree.
  • Document the exact StatiCrypt version pin for reproducible builds.

Rebuild it from scratch

  1. Separate source from output
    Plaintext notes at the repo root (or a restore dir), gitignored; only docs/ is committed.
  2. Stage safely
    rsync into a build dir excluding .git, build artifacts, and every tooling file by name.
  3. Obfuscate
    scrypt(password, salt) → HMAC per path → 16-hex token; rename dirs/files and rewrite links; keep index.html.
  4. Flatten
    Inline CSS/JS/images into each page; rebuild dead SPA shells as static link pages; delete orphans.
  5. Index + encrypt
    Build the search index into index.html; StatiCrypt-encrypt every page with a shared salt; convert remember-me to sessionStorage.
  6. Gate
    A verify.sh that strips ciphertext runs then greps for only-HTML, payload-present, neutral-meta, and no fragments/secrets; exit non-zero on any failure.
  7. Publish
    publish.sh: build → verify → sequential commit → fast-forward push; a decrypt.sh for recovery.
