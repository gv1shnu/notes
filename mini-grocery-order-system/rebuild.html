Decisions

decisionwhytrade-off
Serialize on SQLite's write lock (pessimistic, whole DB)correct by construction at this size; no retry logicevery order is serialized globally, even orders for different products
Prove the guarantee with a test that fails without itthe transaction looks removable; the test makes it non-negotiablea slower, more involved test with a file DB, WAL and a barrier
Outcome enum instead of exceptions or boolexpected failures aren't exceptional; the controller maps reasons to status codesone more type to maintain
409 for insufficient stock, 404 for a missing productclients can branch on the status code alonediffers from the original 400-for-everything contract
TimeProvider injectedfixes the year-1 timestamps and makes the clock testable–
Migrate on boota fresh clone runs with no undocumented stepa real deployment would migrate as a separate step
CI fails on vulnerable packagesthe dependency pins can't silently go stalea new advisory upstream can turn the build red without any code change
One product per order, no basketthe original brief fixed the schema; more rows don't make the concurrency question more interestingnot a realistic order model

How I judge it

  • Invariant: 50 concurrent orders on stock 10 → exactly 10 succeed, stock 0, 10 orders recorded.
  • Counter-proof: with the transaction removed, the same test reports 50 successes and stock 9, so the test really can tell.
  • Regression guards: 3 of the 11 tests pin bugs this repo actually shipped (negative quantity, year-1 timestamp, 404/409 confusion).
  • Supply chain: 0 known-vulnerable packages, enforced in CI on every push to master.

Rebuild it from scratch

  1. Project
    dotnet new webapi on .NET 10; add EF Core + the Sqlite provider; connection string Data Source=MiniGrocery.db.
  2. Model + seed
    Product(Id, Name, Price, Stock), Order(Id, ProductId, Quantity, TotalPrice, CreatedAt). Seed three products with HasData, then dotnet ef migrations add.
  3. Repositories
    Interfaces + EF implementations over the scoped AppDbContext, registered with AddScoped.
  4. Service
    Guard quantity ≥ 1, BeginTransactionAsync(), load the product, check that it exists and has the stock, deduct, add the order (price × qty, TimeProvider clock), call SaveChanges once, commit, and return a PlaceOrderResult.
  5. Controllers
    Products: GET all and GET by id. Orders: POST, a switch on the outcome mapped to 200/400/404/409 with Problem(...). Add AddProblemDetails and MapOpenApi.
  6. Boot
    db.Database.Migrate() in a startup scope; UseStaticFiles for the small HTML frontend; public partial class Program for the tests.
  7. Tests
    A WebApplicationFactory on a temp SQLite file (WAL, 30 s timeout). The concurrency test releases 50 requests through one barrier and asserts 10 / 0 / 10. Then delete the transaction once and watch it fail.
  8. CI
    A GitHub Actions job: restore, Release build, test, and dotnet list package --vulnerable --include-transitive, failing if any are found.
