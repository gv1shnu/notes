Replacing bool with a reason

enum PlaceOrderOutcome { Placed, InvalidQuantity, ProductNotFound, InsufficientStock } record struct PlaceOrderResult(Outcome, OrderId = 0) Placed(id) / Failed(outcome) controller: Placed → 200 { orderId } InvalidQuantity → 400 "Quantity must be at least 1." ProductNotFound → 404 "No product exists with id N." InsufficientStock → 409 "exceeds the stock on hand" _ → 500

The service says why an order did or didn't go through, and the controller decides which status code expresses that. A missing product and an empty shelf really are different things, and a client shouldn't have to parse prose to tell them apart.

Quantity gets checked twice on purpose: a [Range(1, …)] attribute on the DTO, and a guard in the service for anyone who calls it without going through MVC.

Why it serializes

The test harness

  • Real app, temporary file database: GroceryApiFactory swaps the DbContext onto minigrocery-tests-<guid>.db. It has to be a file, not in-memory, because the concurrency test needs several connections fighting over the same data.
  • WAL mode + a 30 s default timeout: readers and the single writer can coexist instead of failing straight away with SQLITE_BUSY.
  • A real barrier: one TaskCompletionSource created with RunContinuationsAsynchronously releases all 50 requests together. Without that flag, SetResult would resume the waiters one after another on the calling thread.
  • The other ten tests cover the seeded catalogue, 404 on an unknown product, stock deduction + total price, CreatedAt being set, ordering exactly all of the stock, quantity 0 and −5 rejected with stock untouched, 404 and 409.
