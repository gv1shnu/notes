The plan contract

router.parse_plan turns a prompt into an ordered list of validated steps, so one request runs several actions:

{ "steps": [ { "action": "find_image", "query": "photoshoot", "after": "2026-01-01", "before": "2026-01-31" }, { "action": "open_app", "app": "paint" } ] }
actionfieldshandler
find_image / find_video / find_documentquery, optional after/before (YYYY-MM-DD)handlers/search.py
open_appapphandlers/apps.py (fuzzy launch)
veracrypt_createsize_gb (prompts for the password itself)handlers/veracrypt.py
shelltask — any other jobhandlers/shell.py (propose → confirm → run)
unknown—reported, skipped

cli._run_request dispatches each step in order, prints a header when there's more than one, and continues past a failed step so "open paint" still runs when the search finds nothing.

Indexing pipeline

Search & the recognition fix

Search

Query text → same embed model → cosine similarity in numpy over all rows. Sub-second for a personal library (tens of thousands of items). Date phrases become an mtime range. Isolated behind store.search so an ANN index can replace it later.

mtime, not EXIF: good for "files from that month", not authoritative for when a photo was taken. EXIF dating is on the roadmap.

Stopping name hallucination

The captioner receives the filename + a parsed source_handle as identity context. The prompt: map a handle to a real person for portraits; name a recognizable fictional character + franchise; never invent a celebrity from appearance; strip the "Here is a description…" preamble.

palaktiwarii_…jpg before: "Kiara Advani" ✗ after: "Palak Tiwari" ✓

The shell hatch & its safety

VeraCrypt keeps its own handler (not folded into shell) only for the safer password UX: on macOS/Linux VeraCrypt prompts directly, so the secret never enters finder's process, shell history, or the process list.
