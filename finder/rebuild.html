How I judge it (from the validation runs)

  • find_document: "expense tracker of 2025" ranked the budget doc at 82% vs a decoy at 49%.
  • find_image: "kids playing in rain" was the top hit on a synthetic set.
  • date filter: same query scoped to March 2026 → no matches; Jan 2026 → matched.
  • shell safety: "delete everything in …" was flagged RISKY and skipped when declined.
  • incremental: second index run skipped 3/3 unchanged files.

Pending (roadmap)

  • Multi-frame video sampling for better recall.
  • OCR for scanned PDFs / screenshots (text extraction only today).
  • EXIF-based photo dating instead of mtime.
  • A smaller default vision model so the first index isn't slow.
  • Optional ANN index (sqlite-vec / FAISS) past ~100k items.
  • Unit tests for the router contract and store.search.
  • More system actions (mount/unmount VeraCrypt, screenshots) on the same router+handler pattern.

Rebuild it from scratch

  1. Ollama + models
    Pull a router (gemma3), a vision model (qwen2.5vl), and nomic-embed-text.
  2. Store
    SQLite table (path, kind, caption, mtime, size, vector blob); upsert, search (numpy cosine), prune.
  3. Indexer
    Walk scan_dirs; skip unchanged mtime; caption images (and video frames via ffmpeg) with the vision model; extract doc text; embed filename + caption.
  4. Router
    One prompt → strict JSON plan (list of steps); validate each step against the contract.
  5. Handlers
    search (with after/before), apps (fuzzy launch per OS), veracrypt (CLI, password prompt), shell (propose → risk-flag → confirm → run).
  6. CLI
    finder "<request>", index [--reindex] [--kind], status, config; run plan steps in order, continue past failures.
  7. Harden recognition
    Pass filename + handle to the captioner; forbid invented names; strip preambles.
