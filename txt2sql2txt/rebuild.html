How I judge it

  • Offline coverage: does each sample dataset's typical question hit one of the 4 patterns? Misses should say they missed.
  • Explainer correctness: every clause in the query appears in the explanation (WHERE, GROUP BY, HAVING, ORDER BY, LIMIT).
  • Executable SQL: generated SQL runs on PGlite against the loaded dataset without error.
  • Cost per use: ₹0 on the offline path, and ₹0 on free-tier providers.

Pending

  • More offline patterns: joins ("orders with customer names"), date ranges, DISTINCT.
  • Execute "Run ▶" inside a read-only transaction or warn on DELETE/UPDATE without WHERE.
  • Persist the loaded database (PGlite supports IndexedDB storage).
  • Refresh DEFAULT_MODELS; free model names change often.
  • Repo description is empty on GitHub: add one.

Rebuild it from scratch

  1. Skeleton
    One index.html: two tabs (Text→SQL, SQL→Text), a schema textarea, a settings card, a database card. CSS variables for dark/light.
  2. SQL → text offline
    Load node-sql-parser UMD (postgresql build). astify → switch on type → build markdown bullets. Write a 20-line miniMarkdown for bold, code, lists.
  3. Text → SQL offline
    Normalise the question (trim, drop "?", collapse spaces), try the four regexes in order, resolve table names from the schema, build the SQL.
  4. Database
    samples.js with window.SAMPLE_DATASETS=[{id,name,sql}]. Lazy-import PGlite, exec the SQL, copy DDL into the schema box, render result.rows as a table.
  5. LLM adapter
    callLLM(system,user) with three branches (OpenAI-compatible / Anthropic / Gemini). Strip <think> and code fences from replies.
  6. Settings
    provider select, model input with hints, key input with "get a free key" link; save per provider in localStorage.
  7. Ship
    Add .nojekyll, push to main, Settings → Pages → main / root.
