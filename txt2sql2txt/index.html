The problem

Students learning SQL get stuck in two directions: "how do I write this question as SQL?" and "what does this query I was handed actually do?"

I wanted one page that does both, runs the query against a real Postgres, costs nothing to host, and costs nothing to use for the common cases.

The constraint that shaped everything

What I observed

  • SQL → text is a parsing problem, not an AI problem. An AST walk gives a deterministic, instant, clause-by-clause explanation.
  • Text → SQL is the hard direction. Rules only cover common shapes ("count of orders", "top 5 customers by spend"); arbitrary English over an arbitrary schema needs a model.
  • Free reasoning models (e.g. deepseek-r1 on OpenRouter) wrap answers in <think> blocks, which must be stripped.

engine choice per direction

Offline is the default for both. When the pattern engine doesn't recognise the phrasing it says so and suggests switching to LLM, rather than guessing.
