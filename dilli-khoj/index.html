The problem

Teach the DBMS curriculum (Modules 1–8) by making students write real SQL, not watch slides, and make it fun enough that they want to.

A PostgreSQL learning game set in a fictional overgrown Delhi: explore a 3D world, restore twenty archives across seven districts, and solve each by writing a SELECT. Unlimited practice in the browser, but grading and progress are server-authoritative so XP can't be faked. Target: up to 3,000 students on campus Wi-Fi at a ₹0 operating cost.

The core idea: two databases, two trust levels

What shaped it

  • Cheating is the real threat. Anything the browser knows can be forged, so the local run is explicitly untrusted and the server owns every number.
  • ₹0 budget means degrade gracefully (drop hidden runtime cases) before adding paid infrastructure. PGlite moves all practice off the server.
  • Accept any correct query. Grading passes any safe query that matches all result fixtures; the intended syntax is not a hard gate.
  • Help should never block progress. A wrong answer costs nothing; hints/reveals cost XP, so a no-help run tops out at 600 and a full-help run still finishes at 250.
  • Sequential unlock (1→20, difficulty rising with the modules) keeps the curriculum order and reduces load.
