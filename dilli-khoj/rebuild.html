How I judge it

  • Judge scale: 3,000-player local stress run — 600 req/s, p95 7 ms, 0 errors (see Blueprint).
  • Test suite: 157 tests + Chrome/WebKit MacBook browser checks pass.
  • Anti-bypass: can the client fake XP or unlocks? (It can't — the server recomputes.)
  • Economy sanity: economy-validation.mjs checks the 600 / 250 XP bounds hold.
  • Download cost: PGlite WASM payload vs. campus Wi-Fi (2–5 MB/s) — still to be measured at scale.

Rebuild it from scratch

  1. Pick the trust boundary first
    Decide that the browser is untrusted. All grading/XP lives on the server; the client is a renderer.
  2. Content pipeline
    Author questions privately (prompt, schema, sample rows, canonical answer). A generator emits visible content for the browser and hidden fixtures for the judge.
  3. Browser practice
    PGlite in a worker; load the visible sample data; a "Run" that executes locally and is never scored.
  4. Judge
    Supabase RPC that takes query + JWT, runs it under a restricted read-only role against hidden fixtures (≥3 cases), compares result sets, and returns a verdict.
  5. Progress + economy
    A second server identity applies XP/unlock transactions; implement the staged-help economy with the 600/250 bounds; sequential unlock.
  6. World
    Three.js scene; a tiled landscape; an avatar; 20 levels with ambience; a cleared-parcels atlas.
  7. Auth + admin
    Google OAuth (External + published); admin from a server allowlist; a DEV-only Question Studio that never ships answers.
  8. Validate + ship
    Vitest + Playwright; a local stress harness; static frontend on Pages, judge on Supabase with CI.
