Surviving a messy model

extract_json(text)

  1. strip <think>…</think> (reasoning models)
  2. if a ```json fence exists, take what is inside
  3. try json.loads
  4. else slice from first { to last } and try again
  5. else raise, and the caller keeps the stub

normalize_slide rules

  • unknown type → infer from title words (quiz, summary, vs) or code presence
  • has code but type isn't code/quiz → force "code"
  • strip paired **/*/backticks, but never touch the code field (SELECT * FROM t survives)
  • content may arrive as string / list / dict → always a flat list of strings
  • missing title → default ("Summary", "Practice", …)
  • empty slides are dropped; zero slides → ValueError

The block engine

Every slide type is just a recipe that compiles to blocks. The renderer only knows blocks.

Auto-fit: why nothing overflows

chars_per_line = (box_w_in × 72) / (char_w × pt) char_w = 0.50 (proportional) | 0.60 (mono) lines = Σ ceil(len(line) / chars_per_line) height = (lines × pt × 1.2 × spacing + gaps) / 72 pt = max_pt while pt > min_pt: if height(pt) ≤ box_h and (mono → widest fits): return pt pt -= 0.5 return min_pt

An estimate, not real font metrics, but it errs large. Bullets fit between 12–21 pt, code between 7.5–13.5 pt, and short code panels shrink to their content so they aren't mostly empty.

titles use a wider 0.62 char width so the accent rule is pushed below a wrapped title, never into it.

Also: python-pptx shapes carry a theme shadow; _kill_shadow() adds an empty effectLst and deletes p:style so every renderer drops it.
