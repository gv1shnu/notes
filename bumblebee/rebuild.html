Decisions

decisionwhy
One global band-pass, never per-clip/optionalit's what unifies unrelated recordings into one voice — the entire concept
Viterbi (cost-based) matcheroptimal coverage of the message with available clips, not greedy dead-ends
Embed phrases for semantic matchreach for the nearest meaning, not an exact keyword
Seeded randomnessreproducible audio → enables offline WAV+SRT export

How I judge it

  • Illusion: do a dozen sources sound like one damaged speaker? (The band-pass test.)
  • Coverage: how much of a typed message the matcher can voice from the corpus.
  • Reply latency and corpus stats, shown live on the radio.
  • Reproducibility: same seed → identical audio (and a clean export).
  • Ingest robustness: no aborts on early words, no clip-id collisions, graceful on non-English.
  • Unit tests: ingest.test, audio.test, normalize.test.

Rebuild it from scratch

  1. Electron skeleton
    electron-vite with main/preload/renderer and a single typed IPC bridge; a Setup screen that checks ffmpeg/whisper/ollama and recommends models by RAM.
  2. Ingest
    ffmpeg to extract dialogue; prefer existing subtitles, else whisper-cli (auto language); a Speech second pass; cut 48 kHz clips with fades, normalise per source; store in SQLite.
  3. Embed + search
    Embed distinct phrases with nomic-embed-text; a semantic + phrase search over the corpus.
  4. Reply text
    An ollama chat model with a tightened vocabulary and a generation cap; warm it at startup.
  5. Matcher
    A Viterbi cost-based matcher that covers the reply text with available clips.
  6. Audio engine
    Splice clips with tuning static + gaps; route everything through one ~1150 Hz band-pass; seed all randomness.
  7. Radio UI
    A receiver faceplate: tuner, spectrum, a terminal that types in sync and names each station; replay.
  8. Export + package
    Re-render a reply offline to WAV + SRT; build an arm64 .dmg (remember to unpack the vector extension for the packaged app).
