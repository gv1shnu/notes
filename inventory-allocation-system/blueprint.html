The whole business rule

placeOrder(productId, quantity): return sequelize.transaction(async t => { product = findById(productId, t) if (!product) throw PRODUCT_NOT_FOUND if (product.stock < qty) throw INSUFFICIENT_STOCK updateStock(productId, product.stock - qty, t) return create({productId, quantity, status:'SUCCESS'}, t) })

Sequelize's managed transaction commits when the callback resolves and rolls back when it throws. So the service doesn't need any explicit commit or rollback code, and nothing reaches the database unless both writes succeed.

the new stock is computed in JS from the value just read, then written back as an absolute number. That's why the read has to be protected.
