D-3The map is always symmetriccan't tell skill from map advantage otherwise
—Evolution in C#, not Python (GDD deviation)5 floats don't justify a bridge + 2nd toolchain + 2nd determinism story
—Fitness = eggs delivered, not win ratewin-optimising finds degenerate 0-0 equilibria
—Each trait owns a primary action; combat priced by force ratiogives personality leverage; makes fights survivable

How I judge it

  • Q1: do distinct weight vectors cluster into distinct behaviour? (Instrumented; preliminary yes.)
  • Objective health: eggs delivered per match > 0 (the metric that caught the broken sim).
  • Determinism: same seed → byte-identical event log.
  • End-reason distribution: timeouts vs deliveries vs eliminations across a batch.
  • All statistics come from the JSONL log, so any new metric is a query, not new plumbing.

Rebuild it from scratch

  1. Lock the three non-negotiables first
    Fixed timestep + seeded RNG; a Simulation that never calls Unity rendering; an append-only JSONL event log. Everything else depends on these.
  2. World model
    Agent, Raptor, Egg, WorldView with helpers (nearest enemy/teammate/raptor, force ratio); put line-of-sight and pathfinding behind ILineOfSight / IPathfinder.
  3. Utility brain
    Score each action against the world, weighted by a 5-float Personality; give each trait a primary action; price engagement by local force ratio.
  4. Batch runner
    Headless MatchRunner using analytic LOS + grid pathfinder; run thousands of matches and aggregate from the log.
  5. Evolution
    A generational GA with elitism over the 5 floats; fitness = eggs delivered, not wins.
  6. Symmetric arena
    ArenaBuilder/Geometry/Layout; keep it symmetric even when procedurally generated.
  7. View + ship
    A Unity view that only draws sim state; animated models; a game-ci Actions workflow to build WebGL and deploy to Pages (keep runtime colliders, watch the camera).
