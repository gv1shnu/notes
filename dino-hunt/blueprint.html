The load-bearing seam

The Utility brain

Each tick, the brain scores the available actions against the world state, weighted by the agent's personality, and returns the highest. Deterministic — no RNG. Two properties were measured, not assumed:

1 · Leverage

Every trait must decide something. If situation modifiers swamp the weights, all personalities play alike and Q1 is dead on arrival. So each trait owns a primary action (see the cover).

2 · Survival

Agents must be able to lose a fight without dying in it. With perfect aim and long range, any stand-up trade is mutual destruction — so engagement is priced against the local force ratio: outnumbered agents disengage, supported ones press. A firefight becomes a decision, not a coin-flip.

Evolving the personalities

search space = 5 floats in [0,1] method = generational GA + elitism (C#, not Python) runs on = the existing BatchRunner (headless) FITNESS = EGGS DELIVERED, not win rate why not wins = optimising "win" finds degenerate equilibria (camp the choke, run the clock, win 0-0). Score the objective → evolved agents keep doing the interesting thing.

The search space is small enough that a plain GA finds good vectors in minutes — no neural nets, no GPU, no Python. A deliberate deviation from the GDD (which specified Python): five floats don't justify a serialisation bridge, a second toolchain, and a separate determinism story.

personality is a plain weight vector so any learning method can drop in behind the same boundary.

The three non-negotiables (D-1)

  • Determinism: same seed → byte-identical match. Without it, evolution fitness is noise and bugs are irreproducible.
  • Sim/render separation: the simulation never touches rendering. Without it, headless batch mode is impossible.
  • Event log: every statistic is derived from the append-only JSONL log, never stored. Without it, every stat needs its own plumbing.

All three paid off directly: the batch runner exists because the sim had no visual dependencies and its two Unity couplings were already behind interfaces.

The arena

  • Always symmetric (D-3): an asymmetric map makes every AI-vs-AI result ambiguous — you can't tell skill from map advantage. Survives even procedural generation.
  • Dynamic arena generation (milestone 13); raptors kept out of cover blocks; arena thinned for readability.
