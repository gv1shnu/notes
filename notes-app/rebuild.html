Decisions

How I judge it

  • Brief covered: create, list, edit and delete all work, with persistence and a responsive layout. Search, an item on the README's own future list, got ticked off too.
  • Error surface: every route catches errors and returns a JSON {error} with a real status code (400 / 404 / 500), never a stack trace.
  • Gaps an honest review finds: server-side validation doesn't trim; unused ObjectId import in route.ts; no tests; no auth, so anyone with the URL owns every note.

Rebuild it from scratch

  1. Scaffold
    npx create-next-app with TypeScript, Tailwind and the app router. Then npm i mongodb.
  2. Connection helper
    lib/mongodb.ts: read MONGODB_URI (throw if it's missing), connect once, and cache the client and db in module variables.
  3. Type
    lib/types.ts: interface Note { _id; title; content; createdAt; updatedAt }.
  4. Collection routes
    app/api/notes/route.ts: GET sorts by createdAt: -1; POST validates the fields, inserts with both timestamps, and returns 201.
  5. Item routes
    app/api/notes/[id]/route.ts: await params, check ObjectId.isValid, then findOne / updateOne($set + updatedAt) / deleteOne, and return 404 when nothing matched.
  6. List page
    Fetch on mount, render a 1/2/3-column card grid, filter it with a search box, and confirm before a DELETE.
  7. Forms
    The create and edit pages share one shape: trimmed validation, a submitting flag, then router.push('/notes').
  8. Root
    Redirect / to /notes. Put MONGODB_URI in .env.local and run npm run dev.
