The brief

Build a full-stack notes app where you can create, read, update and delete notes, store them in MongoDB, and make it work on a phone as well as a desktop.

It's a small app on purpose. What I cared about was getting the whole loop working in one codebase: React pages → Next.js API routes → MongoDB, with TypeScript types shared across all of it. I built it in one morning, and search came 25 minutes after the first commit.

One repo, both halves

What I observed

  • Validation happens twice, and not quite the same way. The forms reject blank text with .trim(); the API only checks that the field is truthy, so a title of spaces sent straight to the API still gets through.
  • Search runs in the client. It filters the notes already loaded by title or content, case-insensitively. That's instant for a personal notes list, but it won't scale once there's pagination.
  • The list is sorted on the server by createdAt, newest first.
  • Bad ids are caught early: every [id] route checks ObjectId.isValid and returns 400 before it touches the database.
