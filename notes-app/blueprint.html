The app router's folders are the URL map. A page.tsx is something you see; a route.ts is something you call. Dynamic segments like [id] come in as params, which Next 16 hands over as a Promise, so every handler starts with const { id } = await params.

every page is a client component that fetches in a useEffect. There's no server rendering of the data at all.

Connect once, reuse it after that

An edit, end to end

  1. Load
    /notes/edit/[id] reads the id with useParams and calls GET /api/notes/[id]; the response fills the title and content fields.
  2. Validate on the client
    On submit, a blank title or content after .trim() shows an inline error and stops there.
  3. PUT
    The body {title, content} goes as JSON. The route checks ObjectId.isValid (400), then that both fields are present (400).
  4. Write
    updateOne({_id}, {$set: {title, content, updatedAt: new Date()}}); matchedCount === 0 → 404.
  5. Return
    200 {message} → the client goes back to /notes, which fetches the list again.
