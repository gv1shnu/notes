The problem

No two search engines return the same list, so trusting one means only ever seeing one engine's opinion.

Nexus is a metasearch engine that goes wide: one query fans out to Google, DuckDuckGo, a self-hosted SearXNG, Wikipedia, StackOverflow, Reddit and arXiv at once, plus an OSINT module, then merges and ranks everything into one feed with tabs (web, images, videos, news, docs, books, code, academic, wiki, community, OSINT). No API keys, no tracking.

Why go wide: one word, three worlds

What I observed (the web fights back)

  • DuckDuckGo images get 403'd constantly, so images + the "other" tab come from SearXNG (Bing/Google/Flickr/Pinterest), not DDG.
  • Reddit killed unauthenticated .json in May 2026, so the Reddit engine tries OAuth API → Atom search.rss → old.reddit HTML, first that returns posts.
  • Google serves a reCAPTCHA to screenshots, so the comparison panel is rendered from Nexus's own scraper data, labelled as such.
  • Python startup cost is paid every search unless you keep the interpreter warm — so there's a persistent ddgs worker.
  • A URL-fetching endpoint is an SSRF risk — the date resolver is guarded and re-checks after DNS.

quantity over raw speed

The thesis: completeness of information beats latency. Date sort streams live (feels fast); relevance sort needs the whole set at once to rank.
OSINT only fires for a single username (~480 platforms via Sherlock) or a domain (crt.sh subdomains).
