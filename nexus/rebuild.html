How I judge it

  • Coverage: how many engines actually returned, per query (metrics.jsonl → /stats).
  • Latency per engine and cache-hit rate.
  • Filter/dedup trim: how much junk the relevance filter removed.
  • Agreement: does RRF lift the URLs multiple engines surface?
  • Tests: classifier, engines, ranking, server unit tests.

Rebuild it from scratch

  1. Server shell
    Express on :8000 serving the static frontend; /api/search (blocking) and /api/search/stream (SSE).
  2. One engine
    Start with Wikipedia (clean REST/JSON): a module returning {title, url, content, rank}. Fix the result shape here.
  3. Fan-out + merge
    Call engines in parallel with Promise.allSettled; dedup by URL; bucket into tabs.
  4. Ranking
    BM25 over title+content, RRF across engines, priors; squash each to [0,1]; relevance filter on query terms.
  5. Hard engines
    Google WAP scrape; a persistent Python ddgs worker; the Reddit OAuth→RSS→HTML chain; SearXNG via Docker for images.
  6. Classifier
    Rule-based intent detection → engine subset; ?route=auto and a read-only /api/classify.
  7. OSINT
    Port Sherlock's site DB to Node for username lookups; crt.sh for domain subdomains; only fire for single-token queries.
  8. Ops
    TTL cache, metrics to jsonl + a /stats page, an SSRF guard on any URL-fetching endpoint, Dockerfile + render.yaml.
