authorized use only

This is a security-engineering project for assessing systems I own or have explicit written permission to test (my own lab, an in-scope bug-bounty program, a signed engagement). The whole design is built around consent gating: nothing beyond passive reconnaissance runs unless a human opts in with a flag.

The problem

A web-application assessment means running a dozen different specialist tools in sequence, each with its own output format, then stitching the results together by hand.

I wanted one pipeline that orchestrates those tools behind a single stage interface and one typed result model, producing a normalized JSON dataset plus a browsable HTML report, with a strict three-tier safety gate so a careless run can never send attack traffic.

The idea: a tier ceiling

What I observed / designed around

  • Every external tool has a different output shape. Normalising into one typed model (Host, Service, HttpEndpoint, Finding, Exploit, Insight…) means the report never cares which tool produced a fact.
  • A run is long and fragile. Writing results.json after every stage makes it crash-safe and inspectable mid-flight.
  • Tools go missing on different machines. A stage with no installed tool self-skips and notes it, instead of crashing the run.
  • The highest-leverage automation is pre-exploitation correlation: fusing isolated facts into chained leads, so a human operator's first move is obvious. Exploitation itself is for an approved human, not the pipeline.
  • A disabled UI button isn't a safety control. The gate is enforced in the core and server-side.

two front ends, one core

A CLI (recon.py) and a local Flask dashboard (serve.py) that launch scans, stream them live (SSE), and browse past runs. The web layer just wraps the same Orchestrator.
correlate is the odd stage out: it attacks nothing, it reads everyone else's output.
